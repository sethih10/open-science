# Scientific agent architectures: role names, tool declarations and operations

Audience: whoever renames our agents and finishes the tool layer. Every paper and repository linked here was opened on 21 October 2026, repositories through raw GitHub files and the GitHub API; anything not confirmed in the text opened is marked. Our plan is read from `README.md` and `AGENTS.md` sections 2, 3 and 6 to 10 as they stood that evening, with the registry, trace and cache modules already in the skeleton. Style follows `agent-writing-style.md`.

## Conclusion

The surveyed systems name their agents after scientific jobs, a lead that plans, readers and discipline specialists that own one task, critics and reviewers that work in a separate context, and recovery or convergence agents for failed DFT runs, while our roster has no literature reader, no analyst of model doubt and no critic independent of the agent that writes the report. Rename `final-state-planner`, `dft-settings-interviewer`, `geometry-critic` and `dft-job-steward` to `principal-investigator`, `computational-chemist`, `surface-chemist` and `dft-recovery-agent`, add `literature-reader`, `mlip-specialist` and `scientific-critic`, and give every agent an explicit list of the tools it may call, as VASPilot does. Declare each tool once as a typed function over our Pydantic records, registered through the MCP SDK so the schema comes from the signature, carry version, compute lane, requirements, cache key, gate, allowed roles, typed errors and a golden example in its ToolSpec, and first move the server out of the `mcp/` folder, whose name makes `python -m mcp.server` run the SDK's own module, and replace the `FastMCP` import that mcp 2 removed.

## Tool declaration pattern to adopt

Adopt one pattern: the registry stays the single source, each tool is a typed function whose parameters and return value are our Pydantic records, and the server registers it through the MCP SDK so the schema comes from the signature; everything the signature cannot say lives in the ToolSpec.

Fix the server first. `mcp/server.py` imports `mcp.server.fastmcp`, which mcp 2 replaced with `MCPServer`, and `pyproject.toml` installs `mcp[cli]` unpinned under `requires-python >=3.9`, while mcp 2 needs Python 3.11. The local folder `mcp/` also shares the SDK's package name: with the SDK installed, `python -m mcp.server`, the command in `plugin.json`, runs the SDK's own module, which a test in a scratch directory confirmed. Move the server to `finalstate/server.py` with a console script, and either pin `mcp<2`, the API AtomisticSkills' servers import, or port to `MCPServer`.

| Field | What it holds | Copied from |
|---|---|---|
| `name`, `version` | The field's term in snake_case, equal to module and function; a version that enters the cache key and the trace | Ours; ToolUniverse's per-tool cache fingerprint |
| `title`, docstring | A title for people; for the model, what it computes, when to call it and when not | MCP SDK `title` and docstring; paper-qa's when-to-call docstrings |
| `board_steps`, `status` | Board keys; core or extension | Ours |
| Input model | Record parameters with `Field` descriptions, units in names, bounds, `Literal` choices; open thresholds required, no default | MCP SDK; ChemGraph's `ASEInputSchema`; ours |
| Output model | A record that becomes `output_schema` and `structured_content`, plus a short text summary for the model | MCP SDK's two channels; ToolUniverse's `return_schema` |
| `annotations` | Read-only, destructive, idempotent, open-world | MCP `annotations`; ToolUniverse's `readOnlyHint`, `destructiveHint` |
| `lane`, `timeout_s` | Laptop, GPU or HPC; a wall-time limit | `AGENTS.md` section 8; Biomni's `timeout_seconds` |
| `requires` | Modules, executables, environment variables, model weights | ChemGraph's runtime requirements |
| `cacheable`, `cache_key` | Which inputs key the result, with version, calculator and settings hash | ToolUniverse's `cacheable`; our `finalstate.cache` |
| `concurrency` | Safe to run in parallel; batch size | paper-qa's `CONCURRENCY_SAFE`; ToolUniverse's batch limit |
| `gate` | `reads_project` and the checkpoint that must have passed, asked through MCP elicitation with the hook as a second guard | Ours; MCP SDK elicitation; ChemGraph's approval modes |
| `allowed_roles` | The agents that may call it | VASPilot's per-agent tools |
| `errors` | The typed errors it may raise, each with a lifecycle stage | TSAgent's stages; El Agente Potente's typed failures |
| `checks`, `thresholds`, `logs`, `wraps` | As now, with the wrapped library's version and licence | Ours; Biomni's licence notes |
| `provenance` | Each output carries its trace event id; a literature value carries a DOI or URL | DREAMS' registry; Kosmos' citations; our `@traced` |
| `example` | One golden input and output, run as a test | ToolUniverse's `test_examples`; AtomisticSkills' `examples/` |

A sketch of one entry, with the registration call the SDK's `add_tool` accepts:

```python
@register(ToolSpec(
    name="pull_force_screen", version="0.1.0", board_steps=("3.3",), status="core",
    annotations=dict(read_only=True, destructive=False, idempotent=True, open_world=False),
    lane="gpu", timeout_s=3600, requires=("module:fairchem.core",), cacheable=True,
    gate=("reads_project",), allowed_roles=("principal-investigator",),
    errors=(("SettingsNotLocked", "PREFLIGHT"), ("OpenDecision", "PREFLIGHT")),
    example="tests/examples/pull_force_screen_oh_pt111.json"))
@traced(step="3.3", tool="pull_force_screen")
def pull_force_screen(candidates: list[Candidate], calculator: str,
                      threshold_eV_per_A: Annotated[float, Field(gt=0, description="open: team decision")]) -> list[ForceScreen]:
    """One MLIP force call per pair; queue last a pair whose B is pulled back. Call after pair_enumeration, before relaxation."""

# finalstate/server.py
server.add_tool(fn, name=spec.name, title=spec.title, description=fn.__doc__,
                annotations=..., meta=spec.meta(), structured_output=True)
```

Derive the ToolSpec's `inputs` and `outputs` from the signature instead of the strings the registry holds today, and return records instead of `Any`, so the MCP layer publishes an output schema and the registry test no longer has to compare two hand-written lists.
